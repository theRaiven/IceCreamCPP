# IceCream — ядро на C++17

Перенос ядра предоставленного C#-проекта с сохранением папок, типов, названий методов, параметров, порядка алгоритмических шагов и XML-комментариев.

## Открытие

1. Открыть `IceCream.sln` в Visual Studio с установленными компонентами разработки на C++ и Windows SDK.
2. Выбрать `Debug | x64` или `Release | x64`.
3. Собрать решение: **Ctrl+Shift+B**.

В решении два проекта:

- **IceCream.Core** — статическая библиотека с ядром. Папки `Geometry`, `Models`, `Profiles`, `Services` соответствуют C#.
- **IceCream.App** — минимальная точка входа для будущего приложения. Сейчас `main()` просто завершается. Графического окна, демонстрации и вывода в консоль нет.

ViewModel и консольная View из предыдущего переноса удалены: в предоставленном C# их не было. Исходное окно WPF пустое; графический интерфейс на C++ пока не реализуется. Всё ядро относится к слою Model, а App оставлена для будущего интерфейса. Полноценный MVVM появится при реализации View и ViewModel.

Qt и OpenGL не подключаются. Требование OpenGL 3.3 Core относится к будущей графической части и на ядро не влияет.

## Оформление и соответствие C#

- Все **45 блоков XML-комментариев** из ядра C# перенесены в соответствующие `.h`, к объявлениям исходных типов и методов. Текст сохранён дословно, включая исходные опечатки.
- Названия типов, методов, свойств, параметров и основные локальные имена сохранены: `GetRadius`, `BuildContours`, `SignedDistanceTo`, `baseSegments`, `pointIndices` и т. д.
- Пространства имён соответствуют C#: например, `IceCream.Core.Geometry` → `IceCream::Core::Geometry`.
- Свойства классов заменены геттерами с тем же именем: `Mesh` → `Mesh()`, `Points3D` → `Points3D()`. Координаты и параметры простых структур остались полями: `X`, `Y`, `Z`, `BaseHeight` и т. д.
- Поля, необходимые для реализации геттеров, закрыты в `private` и имеют суффикс `_`.
- У всех `if`, `else`, `for`, `while` есть фигурные скобки. Геттеры также оформлены с полноценным телом.
- Табы, скобки на отдельных строках, пустые строки между методами и логическими блоками. Присваивания не разрываются после `=`.
- Возвращены `BuildBase`, `BuildCap`, `AddTriangle`, `AddUniquePoint` и раздельные проходы обхода контуров. Объединения методов и проходов из предыдущего переноса отменены.
- Обычные комментарии алгоритмов и русские сообщения об ошибках также перенесены. Комментарии, относившиеся только к удалённым .NET-проверкам, не требуют отдельного кода в C++.

XML-комментарии сохранены как текст исходника, поэтому в них остались неточности исходной документации: у `AtY`/`AtZ` описан X, а у `SignedDistanceTo` перепутаны знаки. Реальная формула не менялась: расстояние положительно со стороны нормали. Упоминание `ArgumentException` в XML соответствует стандартному исключению C++ в реализации.

## Необходимые различия языков

- `record` и `record struct` заменены классами/структурами. Автоматические `ToString`, сравнение всех полей и прочие сгенерированные возможности C# не добавлены: исходные расчёты ими не пользуются.
- `IReadOnlyList` / `List` — `std::vector`; доступ к внутренним коллекциям — через `const`-ссылки. `foreach` заменён на диапазонный `for`.
- Кортеж треугольника — `std::tuple`; `var (a, b, c)` — `auto [a, b, c]`. Для пары индексов ребра используется `std::pair`.
- `Dictionary` / `HashSet` заменены на `std::map` / `std::set`. Логика подсчёта рёбер и построения контуров сохранена.
- `IRadialProfile` — абстрактный класс с виртуальным деструктором. `IceCreamProfile` владеет основанием через `std::shared_ptr<const IRadialProfile>`: в C++ нельзя просто сохранить ссылку на локальный профиль и рассчитывать на сборщик мусора. Это сохраняет поддержку произвольного радиального профиля и безопасное копирование тела.
- Ссылочные параметры, которым `null` не нужен, принимаются через `const &`. Проверки `null` удалены для значений и ссылок; проверка указателя на базовый профиль сохранена.
- `std::move` используется для передачи уже построенных массивов без повторного копирования. Конструкторы объектов с обязательными параметрами вызываются в списке инициализации.
- Размер коллекции в STL имеет тип `size_t`; индексы сетки остались `int`. Перед сужением потенциально большого размера добавлены проверки диапазона.
- Исключения .NET заменены на стандартные исключения C++. Проверки допустимости геометрических данных сохранены.

## Проверка

Сборка GCC с C++17 и `-Wall -Wextra -Wpedantic -Werror` прошла. Отдельно вне архива проверены объёмы по аналитическим формулам, замкнутость и ориентация сетки, сечения, касания, отверстия, некорректные параметры и копирование тела. Проверки прошли с AddressSanitizer и UndefinedBehaviorSanitizer; проверка утечек отключена из-за ограничений среды.

Проверено наличие всех XML-блоков, скобок у управляющих конструкций и отсутствие переносов после оператора присваивания. MSVC здесь недоступен, поэтому фактическая сборка `.sln` в Visual Studio не проверена. Проект тестов и служебные проверочные скрипты в архив не включены.

Алгоритмические ограничения остались прежними: сечение вычисляется по треугольной сетке; площадь предполагает простые непересекающиеся контуры; объём считается по профилю методом Симпсона; допуск сечения `1e-8` абсолютный.
